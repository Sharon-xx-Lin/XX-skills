## 核心：画界面，不画说明

**每一帧都是一个完整的产品窗口**，看上去应该像产品截图：顶栏、侧边栏、内容区、真实控件、真实文案、真实数据。

### 反例（本 skill 迭代中被明确否掉的做法）

在画板上排一堆卡片，卡片里写文字：

```
┌─────────────────────────┐
│ P4  AI 洞察主页面（核心）  │
├─────────────────────────┤
│ 区域 A · KPI 指标卡 ×4    │
│ 区域 B · 平台热度分布图    │
│ 区域 C · 原始数据表       │
│ [需新增]                 │
└─────────────────────────┘
```

这看着像图，实际是 PRD 的图形化排版。用户的原话是「更像需求解释，但是一点也不清晰」。问题在于：读图的人还是得靠读文字来想象界面，而想象出来的东西人人不同 —— 这恰恰是原型图要消除的。

### 正例

同样的内容，画成真界面：顶栏有面包屑和分享按钮，左侧目录树有真实表名，主区是四张并排的指标卡（卡内有真实数字）、一张柱状图、一张带列头和数据行的表格。研发一眼看到的是「要做什么样的界面」，不是「要做哪些区域」。

### 判断标准

把画好的一帧单独截出来，**能不能被误认为产品截图**？如果一眼看出是文字排版，就还没到位。

## 逐帧：交互靠帧序表达

同一界面连续几帧，**每帧只变一处**。变化点依次是：光标位置 → 控件出现/消失 → 面板内容变化 → 数据落位。

### 不要用一帧加文字描述交互

- ❌ 一个静态框，旁边写「点击后展开下拉菜单」
- ✅ 两帧：第一帧光标停在触发处，第二帧**下拉真的展开着**

### 哪些状态各占一帧

- 输入态（输入框有内容、光标在发送按钮）
- 进行中（转圈、进度条、骨架屏、部分数据已落位）
- 结果态（内容已生成）
- 交互点（光标悬停在关键控件上）
- 变化后（点击产生的结果）
- 弹窗/抽屉/下拉的**展开态**
- 报错态、空状态、边界态

### 帧数把控

一个流程 5~8 帧比较合适。少于 4 帧通常说明有状态被合并成文字了；多于 10 帧往往有相邻帧没有实质差异。

**不要为了帧数拆出不存在的中间态。** 如果 PRD 说「结果生成后展示气泡」，那就是一帧（结果+气泡同时出现），不要拆成「先无气泡」「后有气泡」两帧 —— 那是凭空造状态。

## 比例：按实测画，不为重点让步

这是最容易犯、也最伤的错。

需求重点在某个区域时（比如侧边 AI 面板），很自然会想「把它画大点好突出」。**不要这样做。** 比例一改就画出了真实产品里不存在的界面，线框图失去参考价值 —— 用户会直接说「比例失调很奇怪」。

### 正确做法

**量参考图的像素，别估。** 用 PIL 读设计图，找区域边界：

```python
from PIL import Image
import numpy as np
im = Image.open("设计图.png").convert("RGB")
w, h = im.size
a = np.asarray(im).astype(int)
# 表格区有密集网格线 → 列均值波动大；文字面板 → 波动小
band = a[int(h*0.3):int(h*0.8), :, :]
colmean = band.mean(axis=(0, 2))
sd = np.array([colmean[max(0,x-40):x+40].std() for x in range(w)])
# 从右往左找波动由低跃升为高的位置 = 面板左边界
```

实测例：某产品设计图宽 3894px，AI 面板 1062px，占 **27.3%**。据此设 `AI = 322` / `W = 1180`。

### 突出重点的正确手段

| 手段 | 构件 | 说明 |
|---|---|---|
| 整帧强调 | `emphasis_frame` | 紫色粗框 + 标签，框住核心帧 |
| 局部强调 | `emphasis_area` | 细框 + 引线标签，框住关键控件 |
| 非重点降权 | `table_ghost` | 表格降为灰条结构底，保留上下文不抢注意力 |

`table_ghost` 的作用值得说明：画满真实数据会让 70% 面积被雷同内容占据，读图的人得在几帧一样的表格里找那一小块变化。降为灰条后，视线自然落到真正在变的区域 —— **这是在不改比例的前提下调整视觉权重**。

## 图纸语言约定

图纸语言不属于产品 UI，用固定色：黑色 `#1F1F1F` 做结构标识，紫色 `#6B4DE6` 做批注强调。

| 元素 | 做法 | 构件 |
|---|---|---|
| 阶段分组 | 黑色箭头形横幅，跨在该组画面上方 | `stage_banner` |
| 帧标识 | 深色小标签，帧左上角 | `frame_tag` |
| 保真度 | 深色小标签，标在帧组左侧 | `fidelity_tag` |
| 批注 | 紫色小字，**放帧下方横向铺开** | `anno` |
| 帧间跳转 | 细紫线 + 极短动作标签 | `flow_arrow` |
| 交互落点 | 鼠标光标 | `cursor` |
| 本次新增 | 目录树项加紫色左标记 | `sidebar(added=...)` |

几条约定的理由：

- **批注放帧下方**，不放右侧 —— 放右侧会把帧挤窄，破坏真实比例
- **连线只标极短动作**（「发送」「点击气泡」），连线是辅助不该抢戏
- **保真度分层**：不必所有帧都画到同等精细。主流程高保真，负向/边界流程中低保真即可，用标签说明
- **强调框会外扩 8px**，排布时预留空间

## 排布骨架

```
标题（40px 加粗）
副标题：流程名 + 场景 + 关键输入（16px 二级灰）
一行说明：为什么这样排（13px 三级灰）
────────────────────────────────
[黑色阶段横幅 ①]              [黑色阶段横幅 ②]
[保真度标签]
  [帧标签] ┌──────┐  →  ┌──────┐  →  ┌══════┐ ← 紫框=核心帧
           │ 帧 1 │     │ 帧 2 │     ║ 帧 3 ║
           └──────┘     └──────┘     └══════┘
  紫色批注（帧下方，横向铺开）
────────────────────────────────
[黑色阶段横幅 ③]              [黑色阶段横幅 ④]
  ... 第二行同上
```

- 单帧尺寸：约 1180×660（按产品真实宽高比）
- 帧间距：横向 150~200px，纵向 200px 以上（留批注空间）
- 一行 3 帧比较舒服，超过 4 帧总宽会大到必须缩放，细节就看不清了
- 换行处用曲线连线，标出跨行的动作

## 常见错误清单

生成后对照检查：

- [ ] 每帧是否是完整的产品窗口，而非文字卡片
- [ ] 相邻帧是否**只有一处**实质差异
- [ ] 是否有凭空造的中间态（PRD 没提的状态）
- [ ] 区域比例是否按实测，有没有为了"突出"改尺寸
- [ ] 图标是否都画了实际图形（**空方框占位会让整帧像未完成的草稿**）
- [ ] 表格是否撑满可用高度（留大片空白一眼假）
- [ ] 表格列宽是否占满容器（固定列宽会截断或留空）
- [ ] 文案是否用 PRD 里的真实字段名和业务词汇
- [ ] 批注是否在帧下方，没有挤占画面
- [ ] 强调框有没有压住相邻帧或批注
- [ ] `--check` 是否 0 error（text-overflow 必须修）
- [ ] 有没有依赖圆角或阴影传递语义（画板会丢）
- [ ] 发布后是否看过回读的服务端渲染图
